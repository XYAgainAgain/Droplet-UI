Migrating From Jelly UI

Droplet UI is a fork of Jelly UI by bmson (MIT). Every name the library had under Jelly keeps working, permanently, so the whole migration is one package specifier. This page covers that swap, the short list of things that behave differently, and the complete name tables, generated from the library itself so they cannot drift.

The Swap

Install droplet-ui and point your imports at it. Nothing else has to change on day one: your <jelly-*> markup, --jelly-* tokens, and Jelly* class imports all resolve against the new package.

Terminal Copy 
npm uninstall jelly-ui
npm install droplet-ui
Before and after Copy 
// before
import { JellyButton, jellyToast } from 'jelly-ui';

// after (the Jelly names still export; rename when you feel like it)
import { JellyButton, jellyToast } from 'droplet-ui';

Prefer to change nothing at all? Alias the old name in package.json and 'jelly-ui' keeps resolving, now to Droplet UI:

package.json Copy 
{
  "dependencies": {
    "jelly-ui": "npm:droplet-ui@^0.1.0"
  }
}

Droplet UI restarts its version history at 0.1.0. The package is not on npm yet; the specifier above is the one it will ship under.

What Keeps Working

These are permanent aliases, not a deprecation window. An existing Jelly UI consumer can swap packages without touching its CSS or markup, and leave it that way.

  • Every jelly-* tag. Each one is a thin subclass of its droplet-* element, so el instanceof DropletButton holds for a <jelly-button>, and customElements.get('jelly-button') returns JellyButton. The full list is in Element Names.
  • The root exports JellyElement, JellyBody, JellyConfig, JellyBodyOptions, JellyComponent, jellyToast, and jellyIcon, plus the window.jellyToast global.
  • Every --jelly-* custom property, for reads and writes. Setting a legacy name still styles the component, and reading one (in CSS or through getComputedStyle) still returns the live value. See CSS Custom Properties for the pairs and token precedence for which wins when both are set.
  • data-jelly-mode and data-jelly-motion on <html>. Each is kept in step with its data-droplet-* twin automatically; whichever a page writes last wins, so a page that toggles data-jelly-mode itself keeps working even after setThemeMode().
  • The jelly-theme-change and jelly-motion-change events. Whichever name anyone dispatches, listeners for both the Jelly and Droplet name hear it exactly once, and a page dispatching jelly-theme-change by hand still repaints canvases.
  • The legacy accent form: <droplet-theme accent="var(--jelly-color-background-rose)"> works.
  • The ::part(jelly) canvas part. The canvas now carries part="droplet jelly", so either selector styles it.
  • dist/jelly.js still exists in the package (see below for the one way it changed).

What Is Different

Seven things, one of them an intentional break. Each is small, and most only show up if your code depended on an internal detail.

The Cascade Layer Is Named droplet

The document token sheet now lives in @layer droplet instead of @layer jelly. This only matters if your own CSS declared a layer order that named jelly. Layer order is fixed by first mention, so an unnamed droplet layer would land after your last declared layer, and the library tokens would start beating your overrides. Add droplet to the list where jelly was.

Your stylesheet Copy 
/* before */
@layer reset, jelly, app;

/* after: name droplet where jelly was (keeping jelly is harmless) */
@layer reset, droplet, jelly, app;

This is the one deliberate break. The alternative was carrying a misnamed layer forever, and a one-word fix in the layer list seemed the better trade.

dist/jelly.js Re-Exports dist/droplet.js

dist/jelly.js is now a one-line re-export of dist/droplet.js. If you consume the package through a bundler or import map, nothing changes. If you vendor that single file by copying it into your project, copy droplet.js beside it, or switch your copy to droplet.js directly.

Token Precedence Favors the Jelly Name

If a page sets both --jelly-button-height and --droplet-button-height on the same element, the legacy --jelly-* value wins. That keeps a half-migrated page behaving exactly like Jelly UI, but it also means a stray old token can silently override a new one. Migrate a token family in one sweep rather than one name at a time. Reading either name in your own CSS or JS works everywhere (at the root, in dark mode, inside <droplet-theme>), and getComputedStyle(el).getPropertyValue('--jelly-button-height') still returns 62px.

Canonical Theme Tokens Below the Root Do Not Reach Components Yet

A theme token set under the new name below :root (for example .panel { --droplet-color-background-accent: … }) does not reach the components inside it yet, because the legacy name is linked once on :root and wins. Set theme tokens on :root under either name, use the legacy --jelly-* name for a subtree, or scope the subtree with <droplet-theme>. Component tokens (--jelly-button-height, --jelly-fill, and friends) set on the component itself work under either name, and, exactly as in Jelly UI, do not reach components inside an ancestor or an enclosing component.

Internally Created Elements Are droplet-*

Elements the library creates inside its own shadow roots (the tab bar inside tabs, pagination's buttons) and the toaster that jellyToast() creates are droplet-* now. Only code that reached into a shadow root and queried by tag name would notice.

Console Prefix and uniqueId

Console messages start with [droplet], and uniqueId()'s default prefix is droplet. Update any log filter or test that matched the old prefix.

Canonical Spellings for New Code

Prefer data-droplet-mode and data-droplet-motion (setThemeMode() writes both attributes), and listen for droplet-theme-change and droplet-motion-change. The Jelly spellings keep working and the two names stay in step; these are simply the ones the docs and examples use from here on.

Search and Replace

None of this is required, since the old names stay. When you do want the new spellings, run these in order. No codemod ships; the replacements are simple enough that your editor's regex find-and-replace is the right tool.

Review every hit before accepting it. Your own code may use the word jelly for things that have nothing to do with this library, and a blind replace will rename those too.

Ordered find-and-replace steps for adopting the Droplet UI names
# Find Replace Why this order
1 <jelly- and </jelly- <droplet- and </droplet- Tags in markup. Opening and closing tags together so no element is left half renamed.
2 The regex (?<![-\w])jelly- in CSS selectors (jelly-button, jelly-card > *) droplet- Selectors in stylesheets and querySelector strings. Do this right after markup so styles and DOM stay matched; the lookbehind leaves --jelly-, data-jelly-, and the event names for their own steps below.
3 --jelly- --droplet- Custom properties. Sweep a whole file at once; mixing both names in one scope lets the old one win.
4 data-jelly- data-droplet- Root attributes and scope attributes, in markup and in the scripts that set them.
5 Jelly([A-Z]\w*) (regex) Droplet$1 Class and type imports (JellyButton → DropletButton). Scope it to import lines first, then follow the references.
6 jellyToast dropletToast The toast helper, including the window.jellyToast global if you use it.
7 jellyIcon dropletIcon The icon helper.
8 jelly-theme-change droplet-theme-change Event listeners. Both events fire, so a missed listener still works.
9 jelly-motion-change droplet-motion-change Pages that dispatch the motion event themselves.
10 @layer jelly @layer droplet Layer order declarations. The one replacement that fixes a real behavior change, see above.
11 'jelly-ui' 'droplet-ui' The package specifier, last, so everything above was already tested against the new package through the alias.

While You Are Here

The rename is the quiet part of the fork. These are the surfaces Droplet UI opens that Jelly UI kept closed, and none of them require renaming anything first.

feel and quality attributes
Every canvas component now takes feel and quality. palette and material are parsed and reserved for what comes next, and a data-droplet-substance scope axis is reserved beside them.
data-droplet-* scope attributes
Set a value on any ancestor and it cascades to every component inside, the same way the theme attributes on <html> always have.
Explicit registration
droplet-ui/register exports defineAll() and a helper per element (defineButton(), defineDialog(), and so on); droplet-ui/compat exports defineCompat() for the legacy tags. Importing a single component module no longer registers anything. The root import still registers everything under both names.
droplet-ui/core
The spring physics engine (JellyBody and friends) without the DOM.
Explicit registration Copy 
import { defineButton, defineDialog } from 'droplet-ui/register';
import { defineCompat }               from 'droplet-ui/compat';

defineButton();
defineDialog();
defineCompat(); // only if some markup still says <jelly-*>
